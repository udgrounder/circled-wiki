# update_existing(append) 자동 Gate 경로에 CLI 서브커맨드가 없어 내부 Python 함수를 직접 호출해야 함

- Issue ID: `issue-20260805T013930Z-5f1f203d`
- Recorded at: 2026-08-05T01:39:30.874851+00:00
- Reported by: claude-code
- Reported from: agent
- Area: cli
- Severity: medium
- Release observed: v1-e473ba8f5ed3
- Status: open

## Summary

policy/guide/decision/spec/reference/report Bundle에 대한 update_existing append 자동 Gate(apply_automatic_curation_update + complete_curation_work)는 run_configured_curation_batch를 통해서만 호출되도록 되어 있는데, 이 경로는 config.yaml에 curation adapter가 설정되어 있지 않으면(adapter_disabled) 실행되지 않는다. circled-wiki CLI에는 create-curation-review(Review 카드 생성)와 decide-curation-review(no_bundle/approve 등)만 있고, append 자동 Gate를 직접 트리거하는 서브커맨드가 없다. 이번 세션에서 8건의 append 작업을 처리하기 위해 '.circled-wiki/runtime'을 sys.path에 추가하고 circled_wiki.core.curation_reviews.apply_automatic_curation_update와 circled_wiki.core.curation_queue.complete_curation_work를 임시 스크립트(/tmp/append_curation.py)로 직접 import해 호출했다. CLI 계층을 우회해 Runtime 내부 함수를 직접 호출하는 것은 매번 base_body_checksum 계산, CurationOutput 검증, 큐 완료 처리를 에이전트가 직접 재현해야 해서 실수 위험이 있고, 공식 CLI 표면적과 실제 운영에 쓰이는 경로가 어긋난다.

## Expected result

adapter가 비활성화된 상태에서도 append 자동 Gate(update_existing, policy/guide/decision/spec/reference/report 대상)를 실행할 수 있는 circled-wiki CLI 서브커맨드(예: apply-automatic-curation-update)가 있어야 함

## Actual result

해당 경로는 run_configured_curation_batch 내부에서만 호출되고 CLI로 노출되어 있지 않아, adapter_disabled 상태에서 에이전트가 직접 Python 함수를 import해 호출하는 방식으로 우회했음

## Impact

CLI 서브커맨드가 없는 한, adapter_disabled 상태에서의 append 자동 Gate 처리는 매번 에이전트가 임시 스크립트를 새로 작성해 Runtime 내부 함수를 직접 호출해야 하며 이는 반복 작업이자 실수 위험 요소임
