# propose-update의 suggested_bundle_type이 taxonomy routing_hints와 독립적이라 혼동 소지 + candidate_bundles 검색 품질 신뢰도 낮음

- Issue ID: `issue-20260810T073912Z-ad9cb238`
- Recorded at: 2026-08-10T07:39:12.658970+00:00
- Reported by: kjkim
- Reported from: agent
- Area: runtime
- Severity: low
- Release observed: v1-d6eaff98375c
- Status: open

## Summary

propose-update --evidence <id> 출력에서 두 가지 참고사항을 발견했다. (1) suggested_bundle_type은 curator.py의 _suggest_bundle_type()이 만드는 별개의 키워드 휴리스틱으로, curation-taxonomy.yaml의 routing_hints와 무관하게 계산된다. 실제 테스트에서 '임원회의' Evidence에 대해 routing_hints는 taxonomy 규칙대로 bundle_type=report를 정확히 반환했지만 같은 응답의 suggested_bundle_type은 guide였다. 코드 주석엔 'non-binding hint'라고만 되어 있어 두 필드가 충돌할 수 있다는 걸 CLI 출력이나 문서에서 명시하지 않는다. (2) candidate_bundles는 search 명령과 동일한 인덱스를 쓰는 것으로 보이는데, 이 인덱스는 이전에 '방문자 수' 검색 시 무관한 결과(캠핑장 정렬기능 Bundle)를 반환한 적이 있어 완전한 의미 기반 매칭이 아닐 수 있다. candidate_bundles가 비어 있다고 신규 Bundle 생성이 확정적으로 맞다고 보기엔 근거가 약할 수 있다.

## Expected result

1) propose-update 응답 또는 관련 문서(curation-taxonomy.md 등)에 'routing_hints가 존재하면 suggested_bundle_type보다 우선한다'는 안내가 명시되어야 한다. 2) candidate_bundles 검색의 신뢰 범위(키워드 기반 vs 의미 기반)가 문서화되어, Curator가 빈 결과를 얼마나 신뢰해야 하는지 판단할 수 있어야 한다.

## Actual result

curator.py의 _suggest_bundle_type 함수 docstring에 'non-binding curation hint'라고만 적혀 있고 routing_hints와의 우선순위 관계는 어디에도 명시되지 않음. candidate_bundles의 검색 알고리즘/신뢰도에 대한 문서도 없음.

## Impact

낮음 — 둘 다 Curator(Agent 또는 사람)가 최종 판단하므로 데이터 오염 위험은 낮지만, 자동화 수준이 높아질수록(예: auto_create 의존도 상승) 이 두 필드의 암묵적 우선순위·신뢰도 차이가 잘못된 자동 판단으로 이어질 수 있음.

## Reproduction or context

임원회의 관련 Evidence로 propose-update 실행 시 routing_hints[0].bundle_type='report'인데 suggested_bundle_type='guide'로 서로 다르게 반환됨(재현 가능).
