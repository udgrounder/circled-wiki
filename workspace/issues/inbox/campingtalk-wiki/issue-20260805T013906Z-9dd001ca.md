## Summary

decide-curation-review(no_bundle)와 apply_automatic_curation_update 이후 complete_curation_work가 소비된 큐 작업을 workspace/task/curation_reconciliation/<uuid>.md에서 workspace/task/.archive/curation_reconciliation/<uuid>.md로 이동하는데, 이 archive 경로는 원본 디렉토리의 하위가 아니라 형제(sibling) 디렉토리다. 'git add -A workspace/task/curation_reconciliation/'처럼 원본 디렉토리만 지정하면 삭제만 스테이징되고 새 archive 파일은 누락된다. 실제로 지난 curation 배치(2026-08-04 계열)의 no_bundle 처리 archive 기록 20건이 이 문제로 커밋에서 누락되어 있던 것을 이번 세션에서 발견해 사후 커밋(ee92acd)으로 반영했다.

## Expected result

큐 작업 완료 시 원본과 archive가 같은 상위 트리 안에 있거나, 관련 문서에 두 경로를 함께 커밋해야 한다는 안내가 명시되어 있어야 함

## Actual result

두 경로가 서로 다른 상위 디렉토리(workspace/task/ vs workspace/task/.archive/)에 있어 관례적인 git add 패턴에서 누락되기 쉽고, 실제로 여러 날 동안 누락된 사례가 있었음

## Impact
