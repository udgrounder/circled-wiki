# apply_automatic_curation_update이 다중-Evidence append 후 evidence_checksums 스냅샷을 기록하지 않아 promote-curation-candidate가 실패함

- Issue ID: `issue-20260806T024148Z-b5832e2c`
- Recorded at: 2026-08-06T02:41:48.759136+00:00
- Reported by: kjkim
- Reported from: user
- Area: runtime
- Severity: medium
- Release observed: v1-fef5595e5df4
- Status: open

## Summary

direct-creation 타입(report/guide 등) Bundle을 create-bundle로 만들면 extensions.curation.evidence_checksum(단일)이 설정되지만, 이후 apply_automatic_curation_update()로 추가 Evidence를 append할 때는 extensions.curation.automatic_update_receipts에만 기록하고 evidence_checksums(dict)/evidence_checksum을 갱신하지 않는다. Evidence가 2개 이상인 상태에서 promote-curation-candidate --automated를 호출하면 'candidate promotion requires per-Evidence checksum snapshots' 오류로 실패한다. 오늘 2건(CA/Web 기능티켓 Bundle, 캠핑장 신규입점 사례집 Bundle)에서 재현되어 매번 frontmatter를 직접 backfill해야 승격이 가능했다.

## Expected result

apply_automatic_curation_update()가 append 성공 시 extensions.curation.evidence_checksums에 현재 evidence 목록 전체의 checksum 스냅샷을 자동으로 갱신해, 이후 promote-curation-candidate --automated가 별도 수동 backfill 없이 바로 성공해야 한다.

## Actual result

apply_automatic_curation_update()는 automatic_update_receipts 리스트에만 append하고 evidence_checksums/evidence_checksum 필드를 건드리지 않는다. 이 상태에서 promote-curation-candidate --automated를 호출하면 candidates.py의 promote_curation_candidate()가 'per-Evidence checksum snapshots' 부재로 예외를 던진다.

## Impact

다중 Evidence를 append하는 모든 direct-creation 타입 Bundle 승격이 매번 실패하고, Runtime Agent가 frontmatter를 수동 backfill해야만 진행 가능. Bundle 무결성엔 영향 없으나 정상 경로로는 승격이 막힘.

## Reproduction or context

create-bundle로 report 타입 Bundle 생성(evidence 1개) → apply_automatic_curation_update()를 evidence_id 2개째에 대해 update_mode=append로 1회 이상 호출 → promote-curation-candidate --bundle <id> --automated 실행 시 재현.

## Improvement hint

apply_automatic_curation_update()의 마지막 단계에서 review_curation_candidate()의 evidence_checksums 계산 로직(현재 evidence 목록 전체를 순회해 checksum dict 생성, 1개면 evidence_checksum도 함께 설정)을 재사용해 매 append마다 갱신하도록 통일.
