# 하드 PII 계좌번호 스캐너가 '계좌' 라벨과 숫자 사이에 은행명/이름이 끼어있으면 탐지 실패

- Issue ID: `issue-20260813T191417Z-5205c9f2`
- Recorded at: 2026-08-13T19:14:17.514131+00:00
- Reported by: claude-code
- Reported from: agent
- Area: runtime
- Severity: medium
- Release observed: v1-59a434ccdad7
- Status: open

## Summary

sensitive_data.py의 _ACCOUNT_NUMBER 정규식은 '계좌(번호)?' 라벨 직후(선택적 콜론/공백만 허용) 바로 숫자가 와야 매치되는데, 실제 Notion 데이터에는 라벨과 숫자 사이에 은행명이나 담당자 이름이 끼는 경우가 흔해(예: '환불계좌 : [은행명] [예금주] [계좌번호]', '[은행명] [계좌번호] [예금주]') 이 경우 하드 스캐너가 계좌번호를 놓친다. hard_mask_categories.account_number:true로 설정돼 있어 이런 값은 무조건 자동 마스킹되어야 하는데 실패한 사례 3건을 이번 배치에서 발견해 직접 수정했다.

## Expected result

hard_mask_categories.account_number:true인 설치에서는 '계좌' 라벨과 실제 은행 계좌번호 사이에 은행명이나 사람 이름이 끼어 있어도 Capture/Data-Protection-Review 단계에서 자동으로 마스킹되어야 한다.

## Actual result

3건의 Inbox 문서(도봉구청 드림스타트, 의정부여자고등학교, 천보중학교 2)에서 개인 환불계좌번호가 평문으로 남아 있었다. 그중 1건(천보중학교 2)은 capture_details.sensitive_data_precheck.masked:true, categories:[credential]로 이미 정상 통과된 상태였으나 계좌번호는 놓쳤다 — S3 서명값(credential)은 잡았지만 계좌번호(account_number)는 못 잡은 것으로, 같은 하드 스캔 단계 안에서 카테고리별로 탐지 성공/실패가 갈릴 수 있음을 보여준다.

## Reproduction or context

grep -n 'account_number' .circled-wiki/runtime/circled_wiki/core/sensitive_data.py 로 정규식 확인: r'(?i)(?P<label>계좌(?:\s*번호)?)(?P<separator>\s*[:=]?\s*)(?P<value>\d(?:[\d -]{8,22}\d))' — separator가 콜론/공백만 허용하고 은행명·이름 같은 비숫자 텍스트를 건너뛰지 못함. 대조 사례로 knowledge/inbox/notion/evidence-e87a6d90-...md의 '환불계좌 : ******** 국민 문영희'는 숫자가 라벨 바로 뒤에 오는 순서라서 정상 마스킹됨.

## Improvement hint

_ACCOUNT_NUMBER 정규식의 separator 부분을 '\s*[:=]?\s*(?:[가-힣A-Za-z]+\s*)?' 정도로 완화해 라벨과 숫자 사이에 짧은 은행명 토큰 1개까지는 건너뛰도록 보강하는 방안을 검토. 다만 오탐(예: 일반 문장 속 숫자)이 늘지 않도록 은행명 화이트리스트 또는 토큰 길이 제한과 함께 적용 필요.

## Cause hypothesis

정규식이 라벨-숫자 사이의 개재 텍스트(은행명, 예금주명)를 허용하지 않고 있다. 실제 문서에서는 '계좌 : [은행명] [이름] [번호]' 또는 '[은행명] [번호] [이름]' 순서가 흔하므로, separator 부분에 은행명/이름 성격의 짧은 비숫자 토큰을 관용적으로 허용하는 패턴 보강이 필요해 보인다.
