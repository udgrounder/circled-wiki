# 하드 PII credential 스캐너가 한글 라벨/공백 구분 계정·비밀번호를 탐지하지 못함

- Recorded at: 2026-08-06T01:42:11.542686+00:00
- Reported by: claude-code
- Reported from: agent
- Area: runtime
- Severity: high
- Release observed: v1-fef5595e5df4
- Status: open

## Summary

Notion Inbox 문서(전산기자재 자산관리대장)에 원격제어용 admin/user 계정과 비밀번호가 평문으로 포함되어 있었으나, capture 단계의 sensitive_data_precheck와 review-data-protection의 자동 PII Scan(credential 범주, hard_mask_categories.credential=true) 모두 이를 놓쳤다. Agent가 직접 발견해 Data Protection Review 단계에서 인바 파일을 수동 마스킹하고 checksum을 재계산했다.

## Expected result

'계정 user' / '비밀번호 camping1824!!'처럼 한글 라벨 뒤 공백으로 구분된 비밀번호 값도 credential 하드 마스킹 대상으로 탐지되어야 한다.

## Actual result

circled_wiki/core/sensitive_data.py의 _CREDENTIAL_ASSIGNMENT 정규식이 영어 라벨(api_key, password, token 등)과 ':' 또는 '=' 구분자만 인식해, 한글 라벨('비밀번호', '계정')이나 공백 구분(라벨 뒤 줄바꿈)으로 쓰인 자격증명은 탐지하지 못했다.

## Impact

credential 하드 마스킹이 활성화되어 있음에도 실제 평문 비밀번호가 Evidence/Bundle로 승격될 위험이 있었음. 이번 건은 Data Protection Review 단계에서 Agent가 직접 발견·마스킹해 차단함.

## Reproduction or context

sensitive_data.py의 redact_sensitive_data()에 '계정 user\n비밀번호 camping1824!!' 또는 '비밀번호 camping1824!!' 문자열을 hard_mask_categories={'credential': True}로 전달하면 credential 범주가 detected/masked 되지 않음.
