## Summary

Slack 캡처 항목(2090c2ad, '지식 OS 일일 리포트 분석')에 Claude Code 로그인용 OAuth authorize URL 전체(client_id, code_challenge, state 등 쿼리 파라미터 포함)가 평문으로 캡처되어 있었다. redact_sensitive_data의 _CREDENTIAL_ASSIGNMENT/_PRESIGNED_URL_CREDENTIAL 정규식은 'token=', 'api_key=', AWS presigned 파라미터 등만 감지하며 일반 OAuth authorize 쿼리 파라미터는 감지 대상이 아니다. 이번 건은 사용자 지시로 non_business_confirmed 격리 후 폐기해 실질적 노출은 없었으나, 유사 OAuth 링크가 담긴 대화가 정상 업무성으로 분류되면 그대로 Evidence/Bundle에 평문으로 남을 수 있다.

## Expected result

로그인/인증 플로우 URL의 code_challenge, state, client_id 등 OAuth 쿼리 파라미터도 credential 카테고리로 마스킹되어야 함

## Actual result

해당 패턴이 현재 sensitive_data.py의 정규식 범위 밖이라 마스킹되지 않고 그대로 캡처됨

## Impact

OAuth/로그인 URL이 포함된 정상 업무성 대화가 캡처되면 인증 관련 파라미터가 Evidence 원문에 그대로 보존됨
