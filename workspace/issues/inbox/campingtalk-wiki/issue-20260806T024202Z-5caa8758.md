# create-curation-review --output가 다른 명령과 다르게 파일 경로가 아닌 인라인 JSON 문자열을 요구해 사용성 혼동

- Issue ID: `issue-20260806T024202Z-5caa8758`
- Recorded at: 2026-08-06T02:42:02.139035+00:00
- Reported by: kjkim
- Reported from: user
- Area: cli
- Severity: low
- Release observed: v1-fef5595e5df4
- Status: open

## Summary

create-bundle은 --body-file로 파일 경로를 받는 반면, create-curation-review --output은 JSON 문자열 자체를 인자로 받는다(json.loads(args.output)). 파일 경로를 넘기면 'Expecting value: line 1 column 1' 같은 불명확한 JSON 파싱 오류만 반환해, 같은 CLI 내 다른 명령과의 관례 불일치로 처음 시도 시 실패하기 쉽다.

## Expected result

--output도 --body-file처럼 파일 경로를 받거나(예: --output-file), 최소한 파일 경로처럼 보이는 문자열이 실제로는 JSON이 아닐 때 더 명확한 오류 메시지(예: 'expected inline JSON, got a file path?')를 반환해야 한다.

## Actual result

--output 값을 그대로 json.loads()에 넘기며, 파일 경로 문자열을 주면 JSONDecodeError만 발생해 원인을 바로 알기 어렵다.

## Impact

낮음 — 최초 사용 시 1회 실패 후 원인 파악에 시간이 소요되는 사용성 문제. 데이터 무결성 영향 없음.

## Reproduction or context

circled-wiki.py create-curation-review --evidence <id> --output /path/to/output.json --generated-by x --curation-receipt y 실행 시 재현(파일 경로를 JSON으로 파싱 시도해 실패).

## Related paths or artifacts

- `.circled-wiki/runtime/circled_wiki/cli/__main__.py`

## Improvement hint

--output-file 옵션을 추가해 파일 경로를 받아 내부에서 읽도록 하거나, 최소한 문자열이 '{' 로 시작하지 않고 기존 파일 경로와 일치하면 안내 메시지를 추가.
