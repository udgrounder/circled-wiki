# knowledge/README.md에 도메인·타입 선택 세부 관례가 문서화되지 않아 Curation마다 매번 기존 Bundle을 검색해 재확인함

- Issue ID: `issue-20260807T010048Z-c2b57862`

## Summary

Curation adapter가 비활성 상태라 매 배치마다 Claude Code가 domain·bundle_type·중복 Bundle 여부를 직접 판단해야 하는데, knowledge/README.md는 지원 도메인·provider 목록만 있고 '이런 내용은 이 도메인/타입' 식의 세부 분류 관례가 없다. 예를 들어 'CRM 상담 로그는 날짜별 *-YYYY-MM-DD-supplement.md guide로 쌓는다', '피카푸 관련은 domain=product', '사내 CA/Web 기능티켓은 domain=engineering report' 같은 관례가 여러 세션에서 반복 확인됐지만 문서화되어 있지 않아 매번 grep으로 기존 Bundle을 뒤져 재확인하는 비효율이 발생한다.

## Expected result

knowledge/README.md 또는 별도 Curation 가이드 문서에 주요 반복 주제별(CRM 상담 로그, 사내 기능개발 티켓, 제품별 사례집 등) domain·bundle_type·명명 관례가 정리되어 있어, Curation 시 기존 Bundle 전체 검색 없이도 일관된 분류가 가능해야 한다.

## Actual result

knowledge/README.md의 'Bundle 운영' 절에는 지원 도메인 6개(company/product/engineering/cs/operations/marketing) 목록만 있고, 도메인 내 세부 주제별 분류 기준이나 기존 시리즈 Bundle 명명 관례는 어디에도 문서화되어 있지 않다.

## Impact

낮음~중간 — Bundle 분류 자체는 매번 올바르게 되고 있으나(Validator 통과), 매 배치마다 기존 Bundle 검색에 시간이 소요되고 세션 간 판단 일관성이 보장되지 않음(예: 동일 유형 연락처 마스킹 판단이 세션마다 달라졌다가 사후 정정된 사례 있음).

## Reproduction or context

knowledge/README.md 전체를 읽어도 '캠핑장 신규입점 상담 사례는 어느 domain·type으로 만드는가' 같은 질문에 답이 없음. 매 세션마다 grep -rl로 유사 제목의 기존 Bundle을 검색해 관례를 역추적해야 함.
