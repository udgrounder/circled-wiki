# Hard PII credential scanner misses Korean labels and whitespace-separated values

- Issue ID: `issue-20260806T014211Z-7862c773`
- Area: runtime
- Severity: high
- Release observed: `v1-fef5595e5df4`

## Sanitization note

The original report contained an active credential. It was removed from this
workspace item before product work. The repository history of the originating
project remains the recovery record; do not restore the value into this item.

## Summary

The capture-stage sensitive-data precheck and automatic Data Protection PII
scan do not detect credentials when a Korean credential label is followed by a
value separated by whitespace or a line break. A manual Data Protection Review
caught and masked the value before promotion.

## Expected result

Korean credential labels such as `계정`, `비밀번호`, `패스워드`, and `암호`, with
colon, equals, whitespace, or line-break separators, are classified as the
hard-masked `credential` category.

## Actual result

The credential assignment detector supports English labels and only colon or
equals separators, so the supported Korean label and separator forms are not
redacted.

## Impact

An active plaintext password could survive capture and become eligible for
Evidence or Bundle processing despite the credential hard-mask policy.

## Safe reproduction

Use synthetic values only. Verify that a Korean credential label followed by a
synthetic value after either whitespace or a newline is replaced by the
standard redaction marker and reports the `credential` category.

## Improvement scope

Extend the credential assignment detector with Korean label aliases and
whitespace or line-break separators, without weakening existing URL, OAuth,
or English assignment handling. Add regression tests for each supported form.
