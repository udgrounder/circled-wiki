# critical: load_settings()가 새 JSON Schema  해석 버그로 항상 크래시 — validate·validate-configuration·create-bundle 등 Runtime 전체 마비

## Summary

이번 릴리즈(v1-a237bfbf42c1/v1-0d6a0f378ccb)에서 도입된 config.schema.v1.json 기반 검증(config/schema_validation.py의 validate_yaml_payload)이 jsonschema Draft202012Validator에서 RefResolutionError로 항상 크래시한다. config.schema.v1.json의 $id가 'circled-wiki/config/schema/v1'로, 절대 URI가 아닌 bare relative path인데, 내부 $ref('#/$defs/safeIdentifier' 등) 해석 시 jsonschema RefResolver가 base URI를 자기 자신과 결합해 'circled-wiki/config/schema/circled-wiki/config/schema/v1'로 중복된 URL을 만들고 KeyError -> URL 파싱 실패로 이어진다. load_settings()는 config/settings.py의 organization_id_for() 등을 통해 validate_document()(=validate_repository 전체) 및 create_bundle·promote_curation_candidate·apply_automatic_curation_update 등 거의 모든 Curation 함수에서 호출되어, 이 설치본에서는 'validate'와 'validate-configuration'을 포함한 대부분의 CLI 명령이 100% 크래시한다. 'search'처럼 load_settings를 타지 않는 일부 read-only 명령만 정상 동작 확인.

## Expected result

load_settings()·validate_yaml_payload()가 config.yaml/data-protection.yaml/curation-taxonomy.yaml을 정상적으로 스키마 검증하고, 'validate'·'create-bundle'·'promote-curation-candidate'·'reconcile-inbox' 등 기존에 동작하던 모든 CLI 명령이 이번 업그레이드 이후에도 계속 동작해야 한다.

## Actual result

python3 .circled-wiki/bin/circled-wiki.py validate 실행 시 즉시 Traceback으로 크래시(exit 1): jsonschema.exceptions.RefResolutionError: unknown url type: 'circled-wiki/config/schema/circled-wiki/config/schema/v1'. 직접 재현: python3 -c에서 circled_wiki.config.settings.load_settings(Path('.'))만 호출해도 동일 크래시. validate-configuration도 동일 원인으로 크래시.

## Impact

치명적 — 이 설치본에서 validate, create-bundle, promote-curation-candidate, apply-automatic-curation-update, reconcile-inbox 등 load_settings를 경유하는 거의 모든 쓰기/검증 CLI 명령이 100% 실패한다. search 등 일부 read-only 명령만 동작. 업그레이드 직후 발견되어 아직 이 결함 상태로 커밋된 지식 변경은 없음.

## Reproduction or context

1) 이 설치본에서 python3 .circled-wiki/bin/circled-wiki.py validate 실행 -> 즉시 크래시.\n2) python3 -c "from urllib.parse import urljoin; print(urljoin('circled-wiki/config/schema/v1', '#/$defs/safeIdentifier'))" 만으로는 정상 문자열이 나오는 것으로 보아, 문제는 urljoin 자체가 아니라 jsonschema Draft202012Validator의 $id 기반 resolution-scope push/조합 로직(schema_validation.py 26번째 줄 Draft202012Validator(schema) 생성 시 resolver를 명시하지 않고 스키마의 $id를 그대로 씀)에 있는 것으로 추정됨.\n3) 영향 스키마: .circled-wiki/schemas/config.schema.v1.json($id: 'circled-wiki/config/schema/v1')과 동일 패턴의 curation-taxonomy.schema.v1.json, data-protection.schema.v1.json도 같은 $id 형식이라면 동일 위험.

## Improvement hint

1) 근본 수정: 각 schema.v1.json의 $id를 절대 URI 형식(예: 'https://circled-wiki.dev/schemas/config.schema.v1.json')으로 변경. 2) 또는 schema_validation.py에서 Draft202012Validator 생성 시 $id 기반 자동 scope push와 충돌하지 않는 명시적 resolver/registry를 구성. 3) 이 변경을 반영하는 CI/릴리즈 전 검증에 최소 'circled-wiki validate' 스모크 테스트를 포함해 이런 전면 회귀가 릴리즈 전에 잡히도록 함.
