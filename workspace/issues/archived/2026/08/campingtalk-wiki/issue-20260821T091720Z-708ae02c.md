# review_state: approved인데 promote 안 된 Draft Bundle을 찾을 CLI가 없음

- Issue ID: `issue-20260821T091720Z-708ae02c`
- Recorded at: 2026-08-21T09:17:20.553198+00:00
- Reported by: claude-code
- Reported from: agent
- Area: cli
- Severity: medium
- Release observed: 확인 시점 2026-08-21, 정확한 릴리스 태그 불명
- Status: open

## Summary

kjkim이 review-curation-candidate로 이미 승인(review_state: approved)한 runbook/manual Bundle이라도, 그 뒤 promote-curation-candidate를 누군가 실제로 실행하지 않으면 status: draft에 그대로 남는다. 이 상태를 찾아내는 CLI(list-curation-reviews, list-curation-queue 등)가 없어서, 오늘 knowledge/bundles/ 전체를 수동 grep해서야 2건(ai-promotional-image-production 3주 방치, knowledge-os-operations-pipeline-git-commit-cadence 2주 방치)을 발견했다. list-curation-reviews는 이미 소비된 Review는 보여주지 않고, list-curation-queue는 아직 Evidence가 큐에 남아있는 경우만 보여줘서 이 상태를 포착하지 못한다.

## Expected result

review_state: approved이지만 status: draft인 Bundle(=승인은 됐지만 아직 게시되지 않은 것)을 나열하는 CLI(예: list-pending-promotions)가 있어서, 승인자가 승인 후 promote를 잊어도 나중에 쉽게 찾아 마무리할 수 있어야 한다.

## Actual result

list-curation-reviews는 review 레코드가 decide-curation-review 시점에 소비(review_deleted: true)되므로 승인 이후 상태를 더 이상 추적하지 않고, list-curation-queue는 Evidence 큐 항목만 다룬다. 두 CLI 모두 '승인됐지만 promote 안 된 draft Bundle'을 반환하지 않아, knowledge/bundles/ 전체를 grep -rl '^type: runbook\|^type: manual' 후 status: draft를 직접 필터링하는 것이 유일한 발견 방법이었다.

## Impact

승인권자가 승인했다고 생각한 지식(runbook/manual)이 실제로는 게시되지 않은 채 수 주간 조용히 방치될 수 있음(오늘 실제 2건 발견).

## Reproduction or context

runbook/manual Bundle을 review-curation-candidate --action approve까지 진행하고 promote-curation-candidate를 실행하지 않은 채 방치한 뒤, list-curation-reviews와 list-curation-queue를 실행하면 둘 다 해당 Bundle을 전혀 언급하지 않는다.

## Related paths or artifacts

- `.circled-wiki/runtime/circled_wiki/core/candidates.py`
- `.circled-wiki/runtime/circled_wiki/cli/__main__.py`

## Improvement hint

list-curation-reviews 또는 신규 CLI가 knowledge/bundles/를 순회해 extensions.review_state == 'approved' and status == 'draft'인 항목을 별도로 나열하도록 추가. 또는 review-curation-candidate 승인 성공 응답에 'promote-curation-candidate를 아직 실행하지 않으면 게시되지 않습니다' 같은 안내를 포함.

## Cause hypothesis

review-curation-candidate와 promote-curation-candidate가 별도 CLI로 분리되어 있고, 그 중간 상태(approved-but-not-promoted)를 조회하는 전용 기능이 애초에 설계되지 않은 것으로 추정.
