- Release observed: v1-76bc5306928a

## Summary

knowledge/inbox/notion/에 남아있던 정체 임시 파일(.ingest-7917d0d7-....md, type/content_type 필드가 없는 불완전한 캡처 산출물)이 있을 때 review-data-protection 등 run_automatic_pii_scan을 호출하는 모든 명령이 배치 전체에서 실패했다. ingest.py의 except (FrontmatterError, OSError, ValueError) 절이 FrontmatterError를 import하지 않아 NameError가 발생하며, 원래 의도(잘못된 파일은 건너뛰고 계속 스캔)가 깨진다.

## Expected result

iter_active_inbox_items를 순회하다가 유효하지 않은 Inbox 후보 파일(예: 불완전한 캡처 임시 산출물)을 만나면 조용히 건너뛰고 나머지 배치는 정상 처리되어야 한다.

## Actual result

run_automatic_pii_scan(ingest.py:519, 그리고 동일 패턴이 432/1103/1138줄에도 있음)의 except 절이 정의되지 않은 FrontmatterError를 참조해 NameError를 던지며, 이로 인해 review-data-protection이 대상 intake_id와 무관하게 배치 전체에서 실패했다.

## Impact

정체된 임시 캡처 파일 1개가 inbox 디렉터리에 남아있으면 그날의 전체 inbox 정제 배치(review-data-protection)가 대상과 무관하게 전부 실패한다. 오늘 배치에서 44건 전체가 처음에 실패했고, 원인 파일을 격리한 뒤 재시도해 해결함.

## Reproduction or context

knowledge/inbox/notion/에 type: inbox_item이 없는 임시 파일(.ingest-<uuid>.md, 예: 창원LG 정산 정보만 담긴 frontmatter-only 조각)을 두고 review-data-protection --intake <다른 정상 intake_id> ...를 실행하면 NameError: name 'FrontmatterError' is not defined 로 실패한다.

## Related paths or artifacts

## Improvement hint

ingest.py 상단에 frontmatter 모듈의 실제 예외 타입을 import하거나(예: from .frontmatter import FrontmatterError), 존재하지 않는 이름이라면 except 절에서 제거. 432/519/1103/1138 네 곳 모두 동일 수정 필요.

## Cause hypothesis

frontmatter 파서가 자체 예외 타입을 정의/export하도록 리팩터링되면서 ingest.py의 except 절 임포트가 누락된 것으로 추정.
