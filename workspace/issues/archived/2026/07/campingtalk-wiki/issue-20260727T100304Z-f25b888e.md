# Draft 후보 promote-curation-candidate 게이트가 review_state=approved 21건 전부를 차단함

- Issue ID: `issue-20260727T100304Z-f25b888e`
- Recorded at: 2026-07-27T10:03:04.174237+00:00
- Reported by: claude-code
- Reported from: agent
- Area: runtime
- Severity: high
- Release observed: v1-f2d9efab126c
- Status: triaged

## Summary

list-curation-candidates가 반환하는 review_state=approved, status=draft 21건 전체가 promote-curation-candidate 호출 시 'candidate promotion requires an approved curation review record' 오류로 차단된다. review_curation_candidate(action=approve)는 extensions.curation.review_history만 기록하고 extensions.curation.review_decision.review_id는 채우지 않는데, candidates.py의 promote_curation_candidate는 automated=False(CLI/서비스 경로 고정)일 때 review_decision.review_id 존재를 무조건 요구한다. 결과적으로 CLI로 생성된 21개 draft 후보는 정상 승인 경로로는 promote가 불가능하다.

## Expected result

review-curation-candidate로 approve된 draft 후보는 promote-curation-candidate로 active 전환이 가능해야 한다.

## Actual result

모든 21건에서 동일하게 'candidate promotion requires an approved curation review record' ValueError 발생 (executive-meeting-20260722 대상 실제 커맨드로 재현, 파일 변경 없음).

## Impact

큐레이션이 승인 완료된 21건의 Bundle이 active로 발행되지 못해 지식 발행 파이프라인이 정지됨

## Improvement hint

review_curation_candidate(action=approve)가 review_history 승인을 review_decision과 동등하게 인정하도록 candidates.py 로직을 수정하거나, 두 승인 경로 중 어느 것이 promote 전제조건인지 OPERATING_RULES.md/agent-rules에 명시해야 한다.

## Cause hypothesis

candidates.py promote_curation_candidate()의 review_decision 검사가 review_curation_candidate() 승인 경로와 curation_reviews.py decide_curation_review() 승인 경로를 구분하지 못하고, 후자에서만 채워지는 review_decision.review_id를 전자에도 요구한다.
