## Summary

7/24까지 수집된 Notion/Slack Evidence 41건(9개 정제 후보)에 대해 review-curation-candidate --action approve를 실행하려 했으나, 이 함수가 내부적으로 validate_repository()(전체 저장소 검증)를 호출하고 어디서든 하나라도 invalid하면 롤백·실패하는 구조여서, 이번 요청과 무관한 기존 54건의 invalid 문서 때문에 9건 전부가 동일하게 실패함.

## Expected result

review-curation-candidate는 대상 Bundle과 그 Evidence만 검증하거나, 최소한 이번 요청과 무관한 기존 invalid 문서 때문에 무관한 승인 작업까지 전면 차단되지는 않아야 한다.

## Actual result

python3 .circled-wiki/bin/circled-wiki.py validate 실행 시 validated=163 invalid=54. 오류 breakdown: needs_review PII scan receipt requires pii_scanned: false (25건, Evidence), extensions.pii_scan receipt is required when pii_scanned is true (22건, Evidence, pii_scanned:true인데 pii_scan 영수증 자체가 None), id must be a knowledge URI (7건) + bundle_uuid must be a UUID (7건, 이번에 승인하려던 9개 draft candidate 중 7개가 bundle_uuid에 전체 UUID 대신 8자리 short hash만 저장돼 있어 발생), Runbook 경로 오류 1건. review-curation-candidate 9건 전부 동일한 'candidate review validation failed' 메시지로 실패(파일 롤백은 정상 동작 확인).

## Impact

정제(curation) 파이프라인의 review-curation-candidate/promote-curation-candidate가 이번 요청과 무관한 기존 데이터 결함 때문에 저장소 전체적으로 완전히 막힘. RB-PUB-004(Validator 실패 상태에서는 Publish/Commit 금지)에 따라 이번 41건 Evidence의 9개 정제 후보에 대한 review approve를 CLI로 완료하지 못하고 보류함.

## Reproduction or context
